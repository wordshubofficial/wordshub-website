# WORDS HUB Website — Setup & Deploy Guide

This is a responsive starter site for WORDS HUB. It includes a bilingual (English/Sinhala) homepage, video showcase, blog cards, demo poll, review form and an admin sign-in screen.

## Important before launch
- The design and forms are a starter. Until Supabase is configured, the poll/review forms are demo-only and do not save data.
- The admin dashboard currently provides sign-in and a starting point; content-management actions still need to be connected to the database.
- Never put a Supabase `service_role` key in browser code. Use only the project's publishable/anon key, with Row Level Security (RLS) enabled.
- Create your own admin user privately in Supabase Auth. Do not add public sign-up controls to the admin page.
- Reviews should be moderated before appearing on the public homepage. Add spam protection/rate limits before public launch.

## 1. Preview locally
Open `index.html` in a browser to preview the design. For best results use a local development server or deploy to Netlify. Update social links and YouTube URLs before publishing.

## 2. Create Supabase project
1. Go to https://supabase.com/ and create a project.
2. Open Project Settings → API (or Connect) and copy the Project URL and publishable/anon key.
3. Add the URL and key in both `app.js` and `admin.js`.
4. In Authentication, create your admin user privately. Disable public signups if you do not need them.
5. In the SQL Editor, run the SQL below.

## 3. Starter database SQL
This schema enables visitors to submit reviews, but public visitors can only read reviews marked approved. Only authenticated users can manage posts. Poll results are insert-only for visitors and should be protected further against abuse before production.

```sql
create table if not exists public.posts (
  id bigint generated by default as identity primary key,
  title text not null,
  slug text unique not null,
  excerpt text default '',
  body text default '',
  category text default 'Mindset',
  published boolean not null default false,
  created_at timestamptz not null default now()
);

create table if not exists public.reviews (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) between 1 and 60),
  rating int not null check (rating between 1 and 5),
  body text not null check (char_length(body) between 1 and 1000),
  approved boolean not null default false,
  created_at timestamptz not null default now()
);

create table if not exists public.poll_votes (
  id bigint generated by default as identity primary key,
  choice text not null check (choice in ('Discipline','Confidence','Focus','Goals')),
  created_at timestamptz not null default now()
);

alter table public.posts enable row level security;
alter table public.reviews enable row level security;
alter table public.poll_votes enable row level security;

create policy "Public can read published posts"
on public.posts for select to anon, authenticated
using (published = true);

create policy "Authenticated admins can manage posts"
on public.posts for all to authenticated
using (true) with check (true);

create policy "Public can submit reviews for moderation"
on public.reviews for insert to anon, authenticated
with check (approved = false);

create policy "Public can read approved reviews"
on public.reviews for select to anon, authenticated
using (approved = true);

create policy "Authenticated admins can manage reviews"
on public.reviews for all to authenticated
using (true) with check (true);

create policy "Public can submit poll votes"
on public.poll_votes for insert to anon, authenticated
with check (true);
```

**Admin authorization note:** the example `authenticated` policies treat any signed-in Supabase user as an admin. For a production site, restrict content-management policies to a dedicated admin role or an allow-listed admin user ID, and do not enable public account creation. If more than one account may ever sign in, implement a server-verified admin role (e.g. JWT app metadata/claims) before launch. A secure admin should never rely only on hiding the dashboard in the browser.

## 4. Netlify deployment
1. Create a GitHub account if needed and create a new repository named `wordshub-website`.
2. Upload all files/folders from this project to the repository (keep `assets/wordshub-logo.png`).
3. Sign in at https://app.netlify.com/ and choose **Add new site → Import an existing project**.
4. Connect GitHub and select `wordshub-website`.
5. This is a plain static site: leave Build command blank and set Publish directory to `.` (the repository root).
6. Deploy. Netlify will provide a free `*.netlify.app` address. You can change the site name in Site configuration if the name is available.
7. Open the live site on a phone and desktop to test.

## 5. Before you share the website
- Replace generic YouTube/Facebook/TikTok/WhatsApp URLs with your real channel/page links.
- Replace demo articles and sample video cards with your own real content.
- Configure Supabase keys and run the SQL above.
- Tighten admin policies to an explicit admin role/ID before allowing content changes.
- Add real admin content-management forms (create/edit/delete posts, moderate reviews, manage polls/videos). The current admin page is a secure-login starting point, not a finished CMS.
- Add a privacy notice describing review submissions and analytics if used.
- Test all forms and permissions in a second browser/incognito session.

## Suggested next development step
Once the starter is deployed, build out the full admin CMS with CRUD screens for blog posts, review moderation, poll management and video links, then connect those screens to Supabase with strict RLS policies.
